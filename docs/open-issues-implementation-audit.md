# Open issue implementation audit (#2–#9)

This document separates implemented methodology from evidence that cannot be manufactured by code.

## Implemented in this branch

- **#3 resource-stop bias:** observed-prefix discovery is retained; fixed-grant completers remain separate; common-horizon complementarity includes resource-affected pairs; per-bug opportunities and Wilson intervals are explicit; resource-stop sensitivity bounds show the best/worst unresolved-stop range; all tiers expose one terminal-outcome taxonomy.
- **#4 oracle leakage:** generated endpoints are neutral and seed-permuted; neutral source/compiled leak audits and runtime-parity tests pass; source-order and lexical source-aware placebo probes remain near chance across 100 seeds per family.
- **#5 execution identity:** schema-v4 reports and schema-v2 matrices bind exact harness, lock, algorithm/adapter, runtime/compiler, Node/V8/platform, and external CLI artifacts; mixed resume and mixed summary fail closed. Legacy artifacts remain immutable and require a fresh directory.
- **#6 replication:** formerly static families vary structurally; structural-skeleton audits report effective fixture samples separately from search trajectories; partition ranges are enforced; deterministic repetitions must be explicitly `single` or `environment`; serial order is frozen/counterbalanced; a versioned staged Wilson-precision pilot plan prevents outcome-driven ad hoc stopping.
- **#7 cross-adapter parity:** reports declare observable fields, source privileges, time origin, common/native instrumentation, decomposed phases, typed resource provenance, and explicit null external CPU/RSS; paired instrumentation calibration runs identical decisions with common coverage on/off; generated InkCheck witnesses remain private-replay scored.
- **#8 longitudinal persistence:** deterministic 1–30 revision streams, cold/warm/periodic/ablation arms, fully charged replay/rebase work, recipe-only cross-revision state, bounded pruning, protected rogues, atomic resumable cells, exact revision witnesses, learning curves, edit-class competence, storage cost, complementarity, and break-even accounting are implemented and tested.
- **#9 corpus scale:** a deterministic static/runtime complexity analyzer, checked-in common coordinates, public scale roles/envelope, private local adapter with a no-content/no-path output contract, output/config schemas, and explicit corpus gaps are implemented and tested.
- **#2 rerun protocol:** a generated-matrix audit checks exact identity, duplicate cells, terminal labels, native ceilings, adapter failures, timing, resources, and exact witness replay before promotion.

## Evidence gates deliberately still open

- #2 still requires frozen changed InkCheck and/or InkSwarm candidates, then fresh serial 20- and 60-minute matrices. The stopped historical 60-minute matrix is not completed or rewritten.
- #8 needs repeated validation and blind evaluation sequences before any persistence or swarm product claim. The development smoke is an engineering test, not promotion evidence.
- #9 needs more explicitly licensed projects or owner-authorized aggregate private metadata before population-level claims. No proprietary story is inferred from public proxies.
- External InkCheck child CPU and peak RSS remain unavailable in its current native contract. InkBench records null plus the reason; it does not guess.

An issue should close only when its evidence acceptance criteria are met, not merely because the supporting API exists.
