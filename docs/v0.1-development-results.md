# v0.1 development matrix

This is a characterization run, not a leaderboard or a release claim. It uses development seeds, small samples, one difficulty, a single runtime, and the four in-process strategies. InkCheck was validated separately through its real adapter but was not included in this matrix because its native state unit is not identical to an InkBench choice transition.

## Frozen cell definition

- InkBench generator/policies: 0.1.0 working tree on 2026-08-11
- Runtime: `inkjs` 2.4.0 on Node.js 22.13.1, macOS arm64
- Families: all 11 v0.1 families
- Difficulty: 2
- Fixture seeds: 1, 2, 3
- Search seeds: 1, 2, 3
- Ink story seed: 1
- Algorithms: random, systematic, coverage, minimal swarm
- Budgets: 100 and 500 choice transitions
- Cells: 792; completed: 792; budget overruns: 0

Reproduce with:

```sh
npm ci
npm test
npm run experiment:development
```

## What this says—and does not say

The minimal swarm had no exclusive discovery in this matrix. It was competitive on the casino, loop, revisit, and easy false-novelty controls, but it spent its budget less effectively than the simple baselines on rare prefixes, independent combinations, delayed causes, order, and the boring corridor at 100 transitions. The boss fixture was censored for every strategy at 500 and needs higher-budget cells before it can discriminate.

This does not reject the broader InkSwarm hypothesis. Nine development cells per family cannot establish generalization, and fixture construction may favor checkpoint frontier expansion. It does reject any v0.1 claim that the current swarm is already better or complementary.

The matrix also improved the benchmark itself: an uncapped DFS calibration pass initially starved every loop exit by following the state-changing loop forever. The fixed systematic policy now owns an explicit depth-100 ceiling. That correction was made before the table above was frozen.

## Next empirical work

2. Include the real InkCheck adapter in a wall-time/detection matrix while preserving its native work-unit label.
3. Add official `inklecate` compile and replay validation.
4. Strengthen false-novelty and casino difficulty so success is not saturated at the development budget.
5. Run InkSwarm ablations for colonies, saturation, and the rogue fraction before adding frontier propagation or more biological mechanisms.
6. Inspect why the current colony selector loses ancient decisions and order diversity; require a paired improvement without shallow/casino regression before changing it.
