# v0.2 resource-bounded smoke

This is infrastructure evidence, not an InkSwarm performance claim. It uses one generated fixture and one paired search seed under an intentionally tight memory watermark to verify isolation, checkpoint accounting, graceful partial reports, logarithmic budgets, and matrix resume.

Configuration:

- fixture: `compound-needle`, difficulty 3, held-out fixture seed 101;
- search seed: 101; Ink story seed: 1;
- algorithms: random, systematic, coverage, minimal swarm;
- budgets: 1,000, 3,000, 10,000, and 30,000 choice transitions;
- process guard: 64 MiB heap, 60 seconds per cell;
- execution: one isolated worker per cell;
- progress cadence: 1,000 transitions;
- run contract: `resource-bounded-v2`.

Reproduce the matrix with `npm run experiment:resource-smoke`. Peak memory and timing are machine observations and may vary; seeded choice paths and discovery transitions remain deterministic when no resource boundary truncates them first.

At the largest requested budget:

| Algorithm | Status | Stop | Transitions consumed | First bug discovery | Peak heap MiB | Peak retained checkpoints MiB | Wall ms |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| random | completed | budget | 30,000 | 6,746 | 49.8 | 0.00 | 4,170.9 |
| systematic | completed | search exhausted | 4,524 | 1,505 | 34.3 | 0.26 | 1,464.3 |
| coverage | resource-stopped | memory | 22,720 | — | 65.8 | 0.96 | 34,643.4 |
| swarm | completed | budget | 30,000 | 5,297 | 43.9 | 0.63 | 5,085.8 |

The 64 MiB value is a sampled soft heap watermark below the worker's V8 ceiling, not a claim that process RSS or an individual sample can never pass exactly 64 MiB. The guard checks every 64 transitions and returned the coverage cell's partial evidence instead of losing the process to an out-of-memory abort.

The budget curve matters. On this single cell no strategy found the compound bug at 1,000 transitions; systematic found it at 1,505, swarm at 5,297, and random at 6,746. Coverage had not found it when memory stopped. This confirms that 100/500-transition development cells cannot characterize mature behavior. It does not estimate expected performance, establish emergence, or make the swarm superior: systematic was earlier here, and only repeated held-out mature matrices can support comparative conclusions.

The run also verified completed-cell resume and bounded parent memory. Full item-level coverage remains in atomic per-cell files and final `runs.ndjson`; the parent retains compact reports for summary construction rather than accumulating every coverage hash from every worker.

## 100K envelope follow-up

A second one-cell probe requested 100,000 transitions with the mature preset's 1,536 MiB heap watermark and a deliberately shorter 60-second time guard. It tests end-state honesty at a larger grant; it is still not a comparative estimate.

| Algorithm | Status | Stop reason | Transitions | First discovery | Peak heap MiB | Peak checkpoints MiB | Wall ms |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| random | completed | budget | 100,000 | 6,746 | 52.9 | 0.00 | 13,915 |
| systematic | completed | search-exhausted | 4,524 | 1,505 | 32.7 | 0.26 | 1,350 |
| coverage | resource-stopped | time | 30,016 | — | 87.7 | 1.76 | 60,165 |
| swarm | completed | budget | 100,000 | 5,297 | 55.2 | 0.80 | 22,438 |

The resource boundary behaved as designed across all three terminal cases: requested budget consumed, reachable semantic frontier exhausted, and guarded partial stop. Coverage's simple global priority scan is already a compute bottleneck on this fixture; that result should remain visible rather than being hidden by a completed-only aggregate. Swarm's witness transition remained stable while its bounded colony set stayed small. Neither fact establishes emergent behavior or expected superiority without the preregistered repeated matrix.
